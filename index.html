The gap

The data is already on the farm. The decision still is not.

Fitocrops exists for that gap. Not for another report.

Eyes do not scale

One agronomist cannot walk every edge of every plot in the same week.

Files do not talk

Images, weather, machines, and notebook lines sit in different places.

A model with no face

A notebook result never reaches the person who sprays or irrigates.

No version

If last month’s call cannot be opened again, it cannot be improved.

A confident miss

A score with no “this does not fit” line is worse than silence.

The season moves

The useful answer is for this window, not for a slide deck in the off-season.

Platform

Five modules. One product.

The model is the product. The grower is the user.

Field vision

Images and field readings go in together. The model marks what needs a look this week.

Data pipeline

Ingest, clean, keep a history. Cloud Storage on the way in. BigQuery for the record.

Models

Train and version on Vertex AI. The crop problem sets what the model learns.

Inference

An endpoint the operation can call. Cloud Run or GKE, depending on load.

Grower dashboard

A recommendation on a screen. Not a notebook.

    How a reading moves

    Six steps, from the field to the text the operation opens.

    1. 01

      Field

      An image, a sensor, or a note the farm already keeps.

    2. 02

      Data

      It lands in the pipeline, versioned, so you can go back to it.

    3. 03

      Train

      The crop problem becomes a model. Vertex AI holds the version.

    4. 04

      Infer

      The operation asks. The endpoint answers in that same frame.

    5. 05

      Recommend

      A line on the dashboard. The grower does not open a notebook.

    6. 06

      Adjust

      What the field did comes back. The next model starts there.

    The method

    Limits

    What comes back. What stays out.

    The product is a recommendation with a boundary. The boundary is part of the delivery.

    On the slip

    • The plot cut you sent
    • What the model marked, with the version
    • The window — this week, this pass, this plot
    • What this reading left out
    • A clear miss when the data does not fit
    • The words the operation already uses

    Not on the slip

    • A replacement for the agronomist
    • A yield promise
    • A price list printed before we see the operation
    • A client logo we do not have
    • A hectare count invented for the homepage
    • A notebook the grower has to open

    Stack

    Where the models live.

    Training, storage, and serving sit in one place. Vertex AI, BigQuery, Cloud Storage, Cloud Run.

    Vertex AI BigQuery Cloud Storage Cloud Run GKE IAM
    Stack Architecture
    1. FieldThe file hits Cloud Storage with the plot id.
    2. DataThe pipeline writes a row in BigQuery and keeps what it dropped.
    3. TrainVertex AI serves the pinned version for that crop.
    4. InferCloud Run returns the slip, or a miss.
    5. RecommendThe dashboard shows the line in the operation’s words.
    6. AdjustThe walk note returns and waits for the next version.

    The difference

    Same farm. Two ways of deciding.

    Without a version

    • The image sits in a folder.
    • The weather sits in another tab.
    • The note is in a notebook.
    • The call cannot be opened next month.
    • A miss looks like confidence.

    With Fitocrops

    • The image lands with a plot id.
    • Weather is joined to that plot.
    • The note comes back into the same history.
    • The slip names the version that spoke.
    • A miss is a line, not a guess.
